# 작업 기록 (prompt log)

## v0.2 시세 조회 (2026-10-13)

### 사용한 기법
- 시작 전에 필요한 자료(설명서, 인증키)가 있는지 먼저 확인하고, 없으면 멈추고 요청했다.
- HWP 설명서를 직접 텍스트로 뽑아(임시 폴더의 olefile + 자체 스크립트) 필드 표(docs/api/fields.md)로 정리한 뒤, 문서에 없는 값은 실제 호출로 확인했다.
- 시세 방법은 제안 → 사용자 승인 후 구현했다. 테스트를 먼저 커밋했다.
- 실제 API와 브라우저에서 사례별로 확인했다(시세 있음/건수 부족/취소 포함/직거래 포함).

### 질문과 답
- 주소 입력: 시도·시군구 선택 + 법정동·지번 입력. 집 종류는 사용자가 고른다.
- 방법 승인: 같은 법정동·지번, 전용면적 ±10%, 최근 6개월, 중앙값(짝수면 가운데 두 값 평균), 3건 미만이면 시세 없음.
- 직거래는 계산에서 빼고 목록에 "직거래 · 계산 제외"로 표시. 면적은 전용면적(㎡)만 받고 안내 문구를 단다.
- 빌라는 범위를 넓히지 않는다. 추정값은 매매시세 칸에 자동으로 넣고 표시한다.
- 응답 형식(XML)과 fields.md 커밋은 답이 없어 가정을 밝히고 진행했다.

### 틀린 가정
- 처음 확인 때 docs/api/와 .env.local이 없었다 → 사용자가 추가.
- 설명서는 PDF가 아닌 HWP였다 → 텍스트 추출 도구를 임시로 만들었다.
- 설명서에는 취소 거래 표시값이 없었다 → 실제 응답에서 "O"임을 확인했다. 8월 계약이 10월에 해제된 사례도 있었다.
- 단지명은 API마다 띄어쓰기가 달라(경희궁의아침2단지 / 경희궁의 아침 2단지) 단지명이 아닌 지번으로 맞췄다.
- 광주·전남은 2026-06-30에 새 코드(12xxx)로 바뀌었고, API는 과거 달 자료도 새 코드로만 돌려준다(옛 코드 46110은 0건).
- 구가 있는 시(예: 수원시 41110)는 0건이고 구 코드(41111)로 조회해야 한다 → 시군구 목록에서 13개를 뺐다.
- 화면 확인 중 버그 2개를 찾아 커밋 전에 고쳤다: 시세가 없는 새 조회 뒤에도 이전 집의 추정값이 남음 / 시세를 내지 않았는데 비고가 "계산에 사용"으로 나옴.

### 확인한 증거
- `npm test`: 54개 통과(엔진 38, 시세 16). `tsc`, `lint`, `npm run build` 통과. v0.1 이후 src/rules 변경 없음(git diff).
- 실제 조회:

  - 종로구 구기동 56-8(효성빌라) 61.81㎡ → 3건 중 1건 취소, 2건이라 시세 없음
  - 종로구 내수동 71(오피스텔) 32.43㎡ → 중개 6건 중앙값 28,525만원, 직거래 1건(19,500만원) 제외

- 인증키: 서버 로그, 페이지, 빌드 결과물(.next 전체)에서 검색해 0건.
- 직거래 "직거래 · 계산 제외" 문구는 API 응답으로 분류를 확인했고, 화면 표시는 브라우저에서 따로 보지 않았다.

### Done 결과

## v0.1 규칙 엔진 (2026-10-08)

### 사용한 기법
- 만들기 전에 결과를 바꿀 수 있는 미정 사항을 모두 질문으로 정리한 뒤 답을 받고 시작했다.
- 기준값은 공식 원문을 직접 받아 확인했다(HUG 상품개요 페이지를 내려받아 CP949로 디코딩한 뒤 해당 문장 검색).
- 테스트를 먼저 커밋하고(실패 상태 확인) 엔진을 구현했다.
- 화면은 실제 브라우저에서 값을 입력해 확인했다.

### 질문과 답
- 범위: 초기 설정만이 아니라 규칙 엔진과 입력 폼까지 → 엔진까지 만든다.
- 기준값: 전세가율 70/80%(자체 기준), 선순위 부담률 90% 초과(HUG), 최근 소유권 이전 3개월(자체 기준), 금액은 만원.
- 갑구 체크박스에서 "아무것도 안 고름"을 구분하기 위해 "해당 없음"을 따로 두고, 둘 다 없으면 빠진 값으로 처리.
- 값이 빠졌을 때: 위험이 걸렸으면 위험+빠진 값 목록, 아니면 등급 없이 목록만. 값이 빠졌는데 "안전"이 나오면 안 된다.
- 보증보험·이름 비교는 v0.4 범위라 config에 값과 주석만 둔다.

### 틀린 가정
- "2023.5 시행"이라는 90% 기준 날짜는 HUG 페이지에서 확인되지 않았다(갱신보증 '24.1.1 적용만 있음) → 확인된 내용만 적었다.
- "공시가격 126%"는 페이지에 직접 없고 공시가격 140% × 담보인정비율 90%로 계산한 값이었다. 또한 빌라 전용이 아니라 KB/부동산원 시세가 없을 때 쓰는 2순위 방식이었다 → 140%와 90%를 따로 두었다.
- HUG는 갑구 확인 항목에 가등기를 포함한다 → 사용자 확인 후 규칙 3에 추가하고 CLAUDE.md 규칙 3만 수정.
- HUG에 "선순위채권 ≤ 주택가액의 60%" 조건이 있었다 → v0.4용으로 config에 추가.
- `--no-agents-md`로 만들어도 `next dev`가 에이전트 실행을 감지해 AGENTS.md를 만들었다 → `agentRules: false`.
- create-next-app이 넣은 `@types/node ^20`이 Vitest 5와 충돌했다 → 실제 런타임(Node 24)에 맞춰 `^24`.
- 이유 문구에서 "주의으로" 조사 오류가 있었다(화면 확인 중 발견) → 수정.
- 미리 스테이징해 둔 기본 파일 삭제가 fix 커밋(6150854)에 함께 들어갔다. 기록을 다시 쓰지 않는 규칙에 따라 그대로 두었다.
