# 작업 기록 (prompt log)

## v0.1 규칙 엔진 (2026-10-08)

### 사용한 기법
- 만들기 전에 결과를 바꿀 수 있는 미정 사항을 모두 질문으로 정리한 뒤 답을 받고 시작했다.
- 기준값은 공식 원문을 직접 받아 확인했다(HUG 상품개요 페이지를 내려받아 CP949로 디코딩한 뒤 해당 문장 검색).
- 테스트를 먼저 커밋하고(실패 상태 확인) 엔진을 구현했다.
- 화면은 실제 브라우저에서 값을 입력해 확인했다.

### 질문과 답
- 범위: 초기 설정만이 아니라 규칙 엔진과 입력 폼까지 → 엔진까지 만든다.
- 기준값: 전세가율 70/80%(자체 기준), 선순위 부담률 90% 초과(HUG), 최근 소유권 이전 3개월(자체 기준), 금액은 만원.
- 갑구 체크박스에서 "아무것도 안 고름"을 구분하기 위해 "해당 없음"을 따로 두고, 둘 다 없으면 빠진 값으로 처리.
- 값이 빠졌을 때: 위험이 걸렸으면 위험+빠진 값 목록, 아니면 등급 없이 목록만. 값이 빠졌는데 "안전"이 나오면 안 된다.
- 보증보험·이름 비교는 v0.4 범위라 config에 값과 주석만 둔다.

### 틀린 가정
- "2023.5 시행"이라는 90% 기준 날짜는 HUG 페이지에서 확인되지 않았다(갱신보증 '24.1.1 적용만 있음) → 확인된 내용만 적었다.
- "공시가격 126%"는 페이지에 직접 없고 공시가격 140% × 담보인정비율 90%로 계산한 값이었다. 또한 빌라 전용이 아니라 KB/부동산원 시세가 없을 때 쓰는 2순위 방식이었다 → 140%와 90%를 따로 두었다.
- HUG는 갑구 확인 항목에 가등기를 포함한다 → 사용자 확인 후 규칙 3에 추가하고 CLAUDE.md 규칙 3만 수정.
- HUG에 "선순위채권 ≤ 주택가액의 60%" 조건이 있었다 → v0.4용으로 config에 추가.
- `--no-agents-md`로 만들어도 `next dev`가 에이전트 실행을 감지해 AGENTS.md를 만들었다 → `agentRules: false`.
- create-next-app이 넣은 `@types/node ^20`이 Vitest 5와 충돌했다 → 실제 런타임(Node 24)에 맞춰 `^24`.
- 이유 문구에서 "주의으로" 조사 오류가 있었다(화면 확인 중 발견) → 수정.
- 미리 스테이징해 둔 기본 파일 삭제가 fix 커밋(6150854)에 함께 들어갔다. 기록을 다시 쓰지 않는 규칙에 따라 그대로 두었다.
