# 국토교통부 실거래가 API 요청·응답 필드

출처: 이 폴더의 기술문서 3개(HWP). 각 API의 "b) 요청 메시지 명세", "c) 응답 메시지 명세", "d) 요청/응답 메시지 예제"를 옮겼다. 정리일: 2026-10-13.

- 아파트 매매 실거래가 자료 기술문서.hwp
- 연립다세대 매매 실거래가 자료 기술문서.hwp
- 오피스텔 매매 실거래가 자료 기술문서.hwp

표에서 "필수"는 문서의 항목구분 1, "선택"은 0이다. 문서에 없는 내용은 적지 않았다.

## 1. 공통 정보

| 항목 | 아파트 | 연립다세대 | 오피스텔 |
|---|---|---|---|
| 상세기능(영문) | getRTMSDataSvcAptTrade | getRTMSDataSvcRHTrade | getRTMSDataSvcOffiTrade |
| 요청 주소 | `https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade` | `https://apis.data.go.kr/1613000/RTMSDataSvcRHTrade/getRTMSDataSvcRHTrade` | `https://apis.data.go.kr/1613000/RTMSDataSvcOffiTrade/getRTMSDataSvcOffiTrade` |
| 방식 / 응답 형식 | REST(GET) / XML | REST(GET) / XML | REST(GET) / XML |
| 데이터 갱신 | 일 1회 | 일 1회 | 일 1회 |
| 서비스 시작일 | 2024.07.17 | 2024.07.17 | 2024.07.17 |
| 초당 최대 처리 / 평균 응답 | 30 tps / 500ms | 30 tps / 500ms | 30 tps / 500ms |

- 요청 주소는 각 문서의 "요청메시지" 예제에 쓰인 `https` 주소다. 연립다세대와 오피스텔 문서의 "서비스 URL" 칸에는 `http://`로 적혀 있고, 오피스텔은 "Call Back URL" 칸도 `http://`다.
- 조회 단위는 **시군구(법정동코드 앞 5자리) + 계약년월** 하나다. 주소나 단지로는 조회할 수 없다.

## 5. 문서에 없던 것: 실제 호출로 확인한 결과 (2026-10-13)

호출 조건: 종로구(LAWD_CD=11110), 계약년월 202608, numOfRows=1000. 세 API 모두 `resultCode 000 OK`.
결과 건수: 아파트 23건, 연립다세대 27건, 오피스텔 26건.

| 항목 | 확인한 결과 |
|---|---|
| cdealType(해제여부) | 해제(취소) 거래는 `"O"`, 정상 거래는 빈 값. 연립다세대 1건, 오피스텔 2건이 `"O"`였다 |
| cdealDay(해제사유발생일) | 해제 거래에만 값이 있고 형식은 `"26.10.06"`(YY.MM.DD). 8월 계약이 10월에 해제된 사례가 있어, 지금 정상인 거래도 나중에 해제로 바뀔 수 있다 |
| dealingGbn(거래유형) | `"중개거래"`, `"직거래"` 두 값만 나왔다 |
| excluUseAr(전용면적) | 예: 84.858, 61.81, 32.43. 단위는 여전히 문서에 없으나 값으로 보아 ㎡다 |
| jibun(지번) | 세 API 모두 빈 값이나 "산" 지번 없이 `"56-45"`, `"176"` 형식이었다 (이번 한 달치 기준) |
| 단지명 | 같은 단지라도 API마다 띄어쓰기가 달랐다. 예: 아파트 `경희궁의아침2단지`, 오피스텔 `경희궁의 아침 2단지` |
| JSON 응답 | 문서에 없는 `_type=json`을 붙이면 `application/json`으로 온다. 문서에 없는 기능이므로 이 프로젝트는 XML을 쓴다 |
| 계약일 | `dealMonth`, `dealDay`는 앞에 0이 없다 (예: `2026-8-31`) |
